description: Install or repair ERLA's Python runtime and choose this computer's library folders
---

Set up ERLA on this computer:

0. This must run on the computer itself. If this is a cloud chat with no computer-link tools (`mcp__remote-devices__*`) and no local shell on that computer, stop and tell me to open this chat in the Claude desktop app and choose "Link to this computer" (or start a new chat there); running setup in the cloud installs nothing on my computer.
1. Run `uv --version`. ERLA starts through uv, which also supplies Python 3.11+ if none is installed. If uv is missing, tell me to install it and then fully restart the Claude app (so it sees the new PATH), and stop:
   - Windows (PowerShell): `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`
   - macOS / Linux: `curl -LsSf https://astral.sh/uv/install.sh | sh`
   - or see https://docs.astral.sh/uv/getting-started/installation/
2. Install into the runtime the server uses, not a second one (guardrails G10). The plugin root `${CLAUDE_PLUGIN_ROOT}` is `<plugins>/cache/<marketplace>/<plugin>/<version>`; its runtime folder is `<plugins>/data/<plugin>-<marketplace>` (for `erla@erla-tools`: `<plugins>/data/erla-erla-tools`). If the root is not under a `plugins/cache` folder (an app upload, G10.1), skip the manual install: the server installs its own runtime on first start; go to step 3. Otherwise run, with `CLAUDE_PLUGIN_DATA` set to that runtime folder for this command only:
   - PowerShell: `$env:CLAUDE_PLUGIN_DATA = "<runtime folder>"; uv run --no-project --python ">=3.11" "${CLAUDE_PLUGIN_ROOT}/scripts/launch.py" --install`
   - bash/zsh: `CLAUDE_PLUGIN_DATA="<runtime folder>" uv run --no-project --python ">=3.11" "${CLAUDE_PLUGIN_ROOT}/scripts/launch.py" --install`

   Report the result (several minutes the first time). The first output line names the venv it installed into; it must be inside the runtime folder.
3. Call the erla `site_info` tool (search the tool list first; it may be deferred). If it answers with no `runtime_mismatch`, the running server already matches the install: no reconnect is needed, say so and go on. Otherwise tell me how to restart the server for this surface: in the Claude desktop app (Code tab included) turn the ERLA plugin off and on in Settings → Plugins, or restart the app; `/mcp` exists only in the Claude Code terminal, so never send a desktop user there. Then call `site_info` again. If an index job is running (`index_status`), suggest waiting for it to finish before restarting.
4. If no library is configured, tell me a folder picker is on my screen (the server opens it by itself on first start; it may be behind other windows) and call `add_library_folders()`. If it returns `picker: open`, wait until I say I've chosen, then call it again. Report its `summary` (folders, files, size). If the picker cannot open, ask me for the folder path(s) and call `add_library_folders(paths=[...])`. If a library is already configured (a re-run), do not open the picker: report the folders and `site_info.library_probe` (files on disk, indexed, new/changed/missing, skipped as too large), and take the size from `library_stats` or the library composition table in `erla://site/notes`.
5. Report any warnings (Tesseract, MS Office).
6. The first index starts automatically once the library folder is set. A live progress bar appears above the message box by itself while any index job runs (`/erla-progress` hides or shows it); tell me to watch it there. Report the starting state once with `index_status` (phase and file count). `MuPDF error: format error: invalid code in 2d faxd` lines in the log come from damaged fax-encoded scan images inside some PDFs; the job continues, so mention them as harmless rather than as a failure.
7. Tell me about the control panel: send `/erla` as the whole message (pick the plain `/erla` entry in the slash menu, not one of `/erla:setup`, `/erla:find`, …) and it opens above the message box with status, search, library folders, settings and sources; Esc closes it. It opens only on that command: Claude has no tool that opens it, and typing a request such as "open the ERLA control panel" as chat text does nothing. If it replies "widen the window to see it", the window is too small (the pane is about 36 rows tall): enlarge it and run `/erla` again. If `/erla` arrives in the chat as plain text instead of opening the panel, the plugin's hooks did not register the command for this session: start a new session or turn the plugin off and on.
8. Offer the panel's permission rules. The panel's buttons and the progress bar call ERLA's server themselves, and Claude Code checks those calls as if you had made them. Outside auto mode it asks every time (its *Always allow* does not save a rule for these calls). In auto mode its classifier refuses them ("auto mode blocked ERLA's add_library_folders tool"). Only allow rules in my settings stop this; the plugin cannot grant them itself. Read my user settings file (`~/.claude/settings.json`; on Windows `%USERPROFILE%\.claude\settings.json`; it may not exist yet) and check which of these rules are missing from `permissions.allow`:
   `mcp__plugin_erla_erla__site_info`, `mcp__plugin_erla_erla__library_stats`, `mcp__plugin_erla_erla__library_files`, `mcp__plugin_erla_erla__index_status`, `mcp__plugin_erla_erla__index_start`, `mcp__plugin_erla_erla__add_library_folders`, `mcp__plugin_erla_erla__remove_library_folder`, `mcp__plugin_erla_erla__record_feedback`, `mcp__plugin_erla_erla__export_packet`.
   If none are missing, say so and stop. Otherwise list the missing ones and say what they allow:
   - The first three and `index_status` only read ERLA's status, index and files.
   - `index_start` starts an index refresh.
   - `add_library_folders` and `remove_library_folder` change which folders ERLA reads, never the files in them.
   - `record_feedback` and `export_packet` write only to ERLA's site folder.

   Say that the rules are user-level, so they apply in every project, and that they also let you call these tools without asking. Then ask whether to add them, and add nothing unless I say yes. On my yes, add only the missing rules to `permissions.allow`, keeping every other key and rule unchanged and the file valid JSON, then read the file back to confirm. If the edit is refused (auto mode refuses Claude changing its own permissions), do not try another way. Tell me to switch out of auto mode and run `/erla:setup` again, or to paste the rules into the file myself, and show the lines to paste.
